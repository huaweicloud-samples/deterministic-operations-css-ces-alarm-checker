# 架构说明

## 1. 概述

本实践为 CSS（云搜索服务）集群提供**推荐告警的一键部署与周期巡检**能力：通过 Terraform 拉起集群与配套云资源，并提供两个 Python 工具——为指定集群创建推荐告警规则、周期性检查各集群是否仍符合推荐告警基线。

## 2. 总体架构

```
┌──────────────────────────────────────────────────────────────────────┐
│                            运维/调度侧                                │
│   css_create_alarms.py  ──►  为指定集群创建推荐告警规则                │
│   css_check_alarms.py  ──►   周期巡检各集群告警是否匹配基线             │
│   （独立进程 / 定时任务 / 容器，走控制面 API，无需 VPC 内出网）         │
└──────────────┬───────────────────────────────────────────────────────┘
               │ 华为云 Python SDK（AK/SK 经环境变量注入）
               ▼
┌──────────────────────────────────────────────────────────────────────┐
│                          华为云控制面                                 │
│  CSS 云搜索服务  ◄── list/show 集群详情（取集群配置）                  │
│  CES 云监控     ◄── 创建 / 查询告警规则（命名空间 SYS.ES）             │
│  SMN 消息通知   ◄── 告警触发后推送通知给订阅者                         │
│  IAM 委托       ◄── 授权 CES 跨服务推送（delegated_domain_name）       │
│  LTS 云日志     ◄── 工具运行日志归集                                   │
└──────────────────────────────────────────────────────────────────────┘
```

## 3. 核心组件

| 组件 | 说明 |
|------|------|
| **CSS 集群** | 托管 Elasticsearch 集群（`huaweicloud_css_cluster`），部署于 VPC 私有子网 |
| **CES 告警规则** | 命名空间 `SYS.ES`、维度 `cluster_id`（实测：华为云 CSS 集群指标命名空间为 `SYS.ES`，维度为 `cluster_id`）；6 条推荐指标告警（集群健康/CPU/JVM 内存/磁盘使用率/备份失败） |
| **推荐告警基线** | `status(≥1 黄)`、`status(≥2 红)`、`max_cpu_usage(80%)`、`max_jvm_heap_usage(85%)`、`disk_util(80%)`、`backup_failed_task_count(≥1)` |
| **创建工具** | `src/css_create_alarms.py`：按推荐基线逐条创建告警（CES v2 接口，`resources` 为维度数组结构） |
| **检查工具** | `src/css_check_alarms.py`：列出集群 → 比对每条告警的策略字段（指标/周期/统计/阈值/算子），输出匹配/缺失/不匹配统计 |
| **IAM 委托** | 权限收敛到 `css:*` / `ces:*` / `lts:*`，`delegated_domain_name=op_svc_ces` |
| **网络** | VPC + 私有子网 + 安全组（仅放行 443/9200 出站）；工具为本地运行脚本，经控制面 API 访问，无需 NAT / EIP |

## 4. 推荐告警指标说明

> 指标名取自华为云 `SYS.ES` 集群维度真实指标（ListMetrics 白名单实测，非平台通用名）。

| 指标 | 统计 | 周期(s) | 连续次数 | 比较算子 | 阈值 | 意义 |
|------|------|--------|---------|---------|------|------|
| status | 最大 | 300 | 5 | ≥ | 1 | 集群健康黄色（部分副本缺失） |
| status | 最大 | 300 | 5 | ≥ | 2 | 集群健康红色（数据缺失） |
| max_cpu_usage | 最大 | 300 | 5 | ≥ | 80% | 数据节点 CPU 过载 |
| max_jvm_heap_usage | 最大 | 300 | 5 | ≥ | 85% | JVM 堆内存压力过大 |
| disk_util | 最大 | 300 | 5 | ≥ | 80% | 磁盘使用率过高 |
| backup_failed_task_count | 最大 | 300 | 5 | ≥ | 1 | 自动备份失败任务数 |

> 告警周期取 300s（5 分钟聚合），连续 5 次触发告警；`notification_list` 未配置时告警仅记录不推送。

## 5. 设计要点

- **告警基线集中定义**：推荐指标与阈值在工具与 IaC 中集中声明，便于统一调整。
- **指标名以实测白名单为准**：部署前可用 `ListMetrics` 接口核对命名空间 `SYS.ES` 与维度 `cluster_id` 下可用的指标。
- **凭据安全**：AK/SK 仅经环境变量注入运行进程，不落盘、不入镜像。
- **日志可追溯**：工具运行日志归集到 LTS 日志组，便于审计与排障。
